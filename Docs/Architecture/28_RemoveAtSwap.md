# `RemoveAtSwap`: удаление с заменой последним элементом

## Назначение

`RemoveAtSwap` — общий способ удаления элемента из массива, активная часть которого хранится непрерывно, без свободных ячеек между элементами.

Паттерн не привязан к конкретному массиву, типу элементов или имени счётчика. Он может использоваться в разных подсистемах проекта при выполнении двух условий:

- порядок элементов после удаления не обязан сохраняться;
- последний активный элемент можно перенести на место удаляемого.

Новый элемент в таком массиве добавляется в конец активной части. Последовательный проход обрабатывает только существующие элементы и не проверяет свободные ячейки.

## Как работает `RemoveAtSwap`

При удалении элемента из середины массива на его место переносится последний активный элемент:

```text
до удаления:     [ A ][ B ][ C ][ D ]
удаляем B:             ↑          │
                       └──────────┘
после удаления:  [ A ][ D ][ C ]
```

После переноса количество активных элементов уменьшается. Если удаляется последний элемент, переносить ничего не требуется.

Сама операция выполняет не более одного копирования структуры и не сдвигает все следующие элементы. Благодаря этому:

- удаление не зависит от положения элемента в массиве;
- между активными элементами не появляются свободные ячейки;
- добавление нового элемента по-прежнему выполняется в конец активной части;
- последовательные проходы не обрабатывают пустые элементы.

Цена этого способа — изменение порядка элементов.

## Изменение индекса перемещённого элемента

Если идентификатор элемента одновременно является его индексом в массиве, после переноса последний элемент получает новый индекс и новый адрес.

Например:

```text
элемент D до удаления:    ID = 3
элемент D после удаления: ID = 1
```

Сама структура элемента копируется полностью и сохраняет своё состояние. Однако в других структурах может остаться его прежний идентификатор. Все такие связи должны быть исправлены кодом более высокого уровня.

`RemoveAtSwap` отвечает только за удаление и перенос элемента. Он не знает, где используются идентификаторы перемещённого элемента и как устроены связи конкретной подсистемы.

## Двусторонняя связь

**Двусторонняя связь** — связь между двумя структурами, при которой каждая сторона хранит идентификатор другой стороны.

```text
A хранит ID элемента B
B хранит ID элемента A
```

Если одна из сторон перемещается и получает новый идентификатор, сохранённый внутри неё идентификатор второй стороны позволяет сразу найти связанную структуру и сообщить ей новое значение. Поиск по остальным элементам для этого не требуется.

## Слабая ссылка

**Слабая ссылка** — односторонняя связь, при которой владелец ссылки хранит идентификатор целевого элемента, а целевой элемент не хранит идентификатор владельца.

```text
владелец ссылки → целевой элемент
```

Целевой элемент может хранить общий признак существования слабых ссылок, но это не делает связь двусторонней: по такому признаку нельзя определить владельцев ссылок.

В рамках данного механизма слово «слабая» означает отсутствие обратной ссылки. Отдельного формата идентификатора для неё нет — она хранит тот же идентификатор, что и обычная связь.

Если целевой элемент после `RemoveAtSwap` получает новый идентификатор, напрямую найти владельцев слабых ссылок через сам элемент невозможно. Для их исправления нужен предусмотренный конкретной подсистемой способ поиска: отдельный список, таблица или проход по элементам, которые могут содержать такие ссылки.

## Применение в системе объектов

Массив объектов является одним из мест, где используется этот общий паттерн:

- `ObjectsArray` хранит активные объекты без разрывов;
- `ObjectNum` определяет количество активных объектов;
- `ObjectID` является индексом объекта в массиве;
- `RemoveAtSwap` переносит последний объект на место удаляемого;
- `SmartRemove` восстанавливает внешние связи перемещённого объекта.

Таким образом, `ObjectsArray` не определяет устройство `RemoveAtSwap`, а только применяет его к структурам объектов.

### Двусторонняя связь объектов

Примером двусторонней связи в системе объектов является:

```text
FCharacter.ObjectID ↔ FObjectCharacter.CharacterID
```

После перемещения `FObjectCharacter` поле `CharacterID` остаётся внутри скопированной структуры. Через него можно напрямую получить соответствующий `FCharacter` и заменить сохранённый там `ObjectID`.

Каждый тип объекта самостоятельно знает устройство своих двусторонних связей и способ их восстановления.

### Слабая ссылка объектов

Примером слабой ссылки является UI Anchor:

```text
FObjectUI.AnchorObjectID → FObject
```

UI-объекту необходимо знать, к какому объекту он привязан. Целевой `FObject` при этом не хранит обратный `AnchorID`. Anchor является только частным случаем слабой ссылки; у других типов объектов могут появиться другие односторонние связи.

Наличие хотя бы одной слабой ссылки отмечается у целевого объекта флагом:

```asm
OBJECT_WEAKLY_REFERENCED
```

Флаг сообщает только о существовании слабой ссылки. Он не определяет, где она находится и какая структура её хранит.

### Исправление слабых ссылок объектов

Если перемещён объект с установленным `OBJECT_WEAKLY_REFERENCED`, `SmartRemove` располагает прежним и новым идентификаторами перемещённого объекта:

```text
OldObjectID, NewObjectID
→ проход по активным объектам
→ выбор типов, которые могут содержать слабые ссылки
→ вызов обработчика найденного объекта
→ сравнение сохранённого ID с OldObjectID
→ замена на NewObjectID при совпадении
```

`SmartRemove` не знает расположение и назначение конкретной слабой ссылки. Объект, который может владеть такой ссылкой, самостоятельно проверяет свои поля и решает, требуется ли обновление.

Полный проход выполняется только тогда, когда перемещённый объект действительно имеет признак `OBJECT_WEAKLY_REFERENCED`. Удаление объектов происходит редко, а их количество ограничено значением `OBJECT_MAX`, поэтому такой проход является приемлемой ценой за отсутствие постоянных обратных ссылок и дополнительных таблиц.

## Разделение ответственности

Общий паттерн и его применение разделены следующим образом:

- `RemoveAtSwap` удаляет элемент, переносит последний элемент и сохраняет непрерывность активной части массива;
- код конкретной подсистемы знает смысл идентификаторов и восстанавливает внешние связи;
- владельцы двусторонних связей исправляются напрямую через обратный идентификатор;
- владельцы слабых ссылок находятся способом, выбранным конкретной подсистемой;
- `SmartRemove` является объектной реализацией этой дополнительной обработки.

Корректировка двусторонних и слабых связей объектов пока зафиксирована в `SmartRemove` как `ToDo`. Документ описывает согласованное устройство будущей реализации.
