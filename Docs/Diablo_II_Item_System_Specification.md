# Система предметов Diablo II / Resurrected

Техническая спецификация существующей системы для изучения и последующей адаптации.

Дата составления: 24 октября 2026 года.

**Статус:** справочный документ. Не является утверждённым проектом системы предметов HoMM и не задаёт ей адреса, размеры буферов, структуры или правила экипировки.

## 1. Назначение и границы достоверности

Документ должен позволить программисту проследить всю цепочку: что автор игры задаёт заранее, что выбирается при создании предмета, где хранятся полученные числа, как они участвуют в расчётах и что видит игрок.

Используются три разных вида свидетельств, которые нельзя считать одним исходным кодом D2R:

| Обозначение | Что подтверждено | Чего источник не подтверждает |
|---|---|---|
| **D2R DATA** | Назначение таблиц данных D2R и их столбцов по документации | Точные адреса, указатели и упаковку структур памяти движка |
| **D2MOO 1.10f** | Конкретные C++-структуры и алгоритмы реконструкции D2 1.10f | Побайтовое совпадение с памятью D2R |
| **SAVE TOOL** | Чтение и представление сохранений D2/D2R в стороннем инструменте | Внутренние C++-объявления движка D2R |

Имена [D2UnitStrc](#d2unitstrc), [D2PropertyStrc](#d2propertystrc), [D2StatStrc](#d2statstrc) и физические размеры их полей ниже относятся к **D2MOO 1.10f**. Утверждать, что именно такие структуры с той же упаковкой используются внутри D2R, по изученным источникам нельзя.

Это спецификация рассматриваемой подсистемы данных и свойств, а не полная спецификация всех предметных механик, формул боя, торговли, сетевого протокола и всех версий сохранений.

В примерах прямо помечены условные предметы и числа. Они поясняют устройство и не выдаются за реальные строки игровых таблиц.

## 2. Главный принцип

Система разделяет **заданные данные** и **данные конкретного предмета**.

| Заранее задано | Получено конкретным предметом |
|---|---|
| Описание вида «короткий меч» | Ссылка на этот вид |
| Возможная добавка силы от 5 до 10 | Фактическая прибавка силы +7 |
| Графика и занимаемая область вида | Индивидуальное положение в инвентаре |
| Правило обработки бонуса | Полученное числовое значение |

При создании предмета общие таблицы не превращаются в экземпляр и не переписываются. Игра создаёт индивидуальные данные и использует общие описания по ссылкам или идентификаторам.

Не все значения экземпляра случайны: часть копируется, часть вычисляется, часть изменяется при дальнейшей игре.

## 3. Имена из исходников и различные идентификаторы

**Навигация:** имя описанного типа в тексте и колонке «Тип» ведёт к его разделу в этом документе. В строке «Объявление» отдельно дана ссылка на исходный код. Заголовки и текстовые примеры не являются ссылками.

**Как читать тип:** [D2ItemsTxt](#d2itemstxt) — одна структура с описанием вида предмета. [D2ItemsTxt*](#d2itemstxt) — указатель, то есть поле хранит адрес данных этого типа. Звёздочка не входит в имя структуры. Например, `D2ItemDataTbl.pItemsTxt` хранит адрес первого элемента массива, а `nItemsTxtRecordCount` — число его записей. Сам символ `*` не сообщает длину массива.

В первой колонке приведены имена из D2MOO. Русские пояснения описывают их назначение и не вводят дополнительные структуры.

| Имя в исходнике | Назначение | Примечание |
|---|---|---|
| [D2ItemsTxt](#d2itemstxt) | Общее описание разновидности предмета | Например, короткий меч вообще. Пояснение «базовый вид» не является именем структуры |
| [D2UnitStrc](#d2unitstrc) при `dwUnitType = UNIT_ITEM` | Конкретный предмет во время игры | «Экземпляр предмета», `item instance` — поясняющий термин этого документа. Имя структуры `ItemInstance` в исходниках D2R не установлено |
| [D2ItemTypesTxt](#d2itemtypestxt) | Общие правила категории | Например, категория мечей или щитов |
| [D2MagicAffixTxt](#d2magicaffixtxt) | Описание префикса или суффикса | Настройки возможной магической добавки |
| [D2PropertyStrc](#d2propertystrc) | Параметры назначения свойства | Ссылается на правило [D2PropertiesTxt](#d2propertiestxt) |
| [D2PropertiesTxt](#d2propertiestxt) | Связь свойства с функциями назначения и характеристиками | Одно свойство может назначать несколько характеристик |
| [D2C_ItemStats](#d2c-itemstats) | Перечисление ID характеристик | Не структура предмета |
| [D2StatStrc](#d2statstrc) | Значение одной характеристики с ID и параметром | Не весь предмет |
| `dwCode` | Код вида предмета в общих данных | Позволяет другой таблице указать, на каком виде основан предмет |
| `dwClassId` | Индекс вида в загруженном массиве [D2ItemsTxt](#d2itemstxt) | Получить описание по `pItemsTxt[dwClassId]` |
| `dwUnitId` | Идентификатор конкретного runtime-объекта | Обратиться к одному из двух одинаковых мечей |
| `nProperty` | Индекс записи правила [D2PropertiesTxt](#d2propertiestxt) | Определить, как назначить свойство |
| `nStat` | ID характеристики из словаря характеристик | Определить, что означает сохранённое число |
| `nLayer` | Уточняющая часть ключа характеристики или параметр её создания | Для простого бонуса 0, для некоторых эффектов указывает умение |

`dwCode`, `dwClassId`, `dwUnitId`, ID аффикса и `nStat` не взаимозаменяемы. Число без названия соответствующей таблицы не является достаточным описанием ссылки.

`dwUnitId` здесь не объявляется постоянным идентификатором между сохранениями. ID предмета, записанный в файле сохранения, также нельзя автоматически отождествлять с runtime-полем `dwUnitId`.

Исходные объявления и использование:

- [D2UnitStrc](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/include/Units/Units.h#L110).
- [D2ItemsTxt](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/include/DataTbls/ItemsTbls.h#L287).
- [DATATBLS_GetItemsTxtRecord](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/src/DataTbls/ItemsTbls.cpp#L400).
- [IItem](https://github.com/dschu012/d2s/blob/0da1e024b406fd4c3fffa182faebc6ed539c1cd7/src/d2/types.ts#L303).

### 4.1. `D2ItemDataTbl` — размещение общих описаний

Объявление: [D2ItemDataTbl](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/include/DataTbls/ItemsTbls.h#L450). Это заголовок загруженных таблиц, а не предмет в инвентаре.

| Поле | Тип в исходнике | Что физически хранится | Назначение |
|---|---|---|---|
| `pItemsTxt` | [D2ItemsTxt*](#d2itemstxt) | Указатель на общий массив | Получение описания по индексу |
| `nItemsTxtRecordCount` | `int` | Число записей | Граница массива |
| `pWeapons` | [D2ItemsTxt*](#d2itemstxt) | Указатель на таблицу оружия | Доступ к загруженным описаниям оружия |
| `pArmor` | [D2ItemsTxt*](#d2itemstxt) | Указатель на таблицу брони | Доступ к загруженным описаниям брони |
| `pMisc` | [D2ItemsTxt*](#d2itemstxt) | Указатель на таблицу остальных предметов | Доступ к соответствующим описаниям |

[D2ItemsTxt](#d2itemstxt) не содержит массив других [D2ItemsTxt](#d2itemstxt). Он сам является одной записью массива, на который указывает `pItemsTxt`. Функция [DATATBLS_GetItemsTxtRecord](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/src/DataTbls/ItemsTbls.cpp#L400) получает адрес записи `pItemsTxt[nItemId]`.

Внутри одной [D2ItemsTxt](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/include/DataTbls/ItemsTbls.h#L287) поле `wType` имеет тип `int16_t[2]`: это два **индекса** записей [D2ItemTypesTxt](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/include/DataTbls/ItemsTbls.h#L403). Вложенных структур категории и указателей на них в этом поле нет.

### 4.3. `D2UnitStrc` и `D2ItemDataStrc` — индивидуальные данные

Объявления:

- [D2UnitStrc](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/include/Units/Units.h#L110).

Эти структуры создаются для конкретного предмета во время игры.

| Структура-владелец | Поле | Тип в исходнике | Содержимое и связь |
|---|---|---|---|
| [D2UnitStrc](#d2unitstrc) | `dwClassId` | `int32_t` | **Индекс** общего описания [D2ItemsTxt](#d2itemstxt). Само описание сюда не вложено |
| [D2UnitStrc](#d2unitstrc) | `dwUnitId` | `D2UnitGUID` | Идентификатор объекта. Это не индекс таблицы видов предметов |
| [D2UnitStrc](#d2unitstrc) | `pItemData` | [D2ItemDataStrc*](#d2itemdatastrc) | **Указатель** на индивидуальные сведения. В исходнике находится в объединении указателей для разных видов объектов |

### 4.4. Хранение значений, отдельного эффекта и итогов объекта

Здесь три самостоятельных типа. Сначала описан контейнер чисел, затем список с контекстом эффекта, затем организация списков одного объекта. Ни одна из этих структур не является настройкой диапазона генерации.

#### 4.4.1. `D2StatsArrayStrc`

**Что это:** заголовок массива записей [D2StatStrc](#d2statstrc). Каждая запись содержит ID характеристики, уточняющий параметр и фактическое значение.

**Зачем нужен:** количество характеристик различается. Контейнер хранит, где находятся записи и сколько их. Например, он может содержать записи «сила +7» и «сопротивление огню +13». Сам контейнер не сообщает, кем создан эффект и когда его нужно убрать.

**Куда входит:** непосредственно в поле `Stats` структуры [D2StatListStrc](#d2statliststrc). Этот же тип используется для поля `FullStats` структуры [D2StatListExStrc](#d2statlistexstrc). Это разные контейнеры, хотя у них одинаковый тип.

**Кто заполняет:** код вставки, удаления и изменения характеристик во время игры или восстановления данных.

| Поле | Тип | Что хранится | Где используется и зачем |
|---|---|---|---|
| `pStat` | [D2StatStrc*](#d2statstrc) | Адрес отдельно выделенного массива записей | Поиск и расчёты получают запись по этому адресу. Внутри заголовка нет встроенного массива всех значений |
| `nStatCount` | `uint16_t` | Количество используемых записей | Поиск и перебор ограничиваются этим количеством. При значении 2 действуют записи с индексами 0 и 1 |
| `nCapacity` | `uint16_t` | Количество записей, под которые выделена память | Вставка проверяет, нужно ли увеличить выделенную область. При количестве 2 вместимость может быть больше 2 |

`nGrowthAmount` и `nShrinkThreshold` — статические константы управления памятью из объявления. Они не являются полями отдельного контейнера.

Объявление в исходнике: [D2StatsArrayStrc](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/include/D2StatList.h#L445).

#### 4.4.2. `D2StatListStrc`

**Что это:** один список характеристик вместе с контекстом их действия. Значения находятся в его поле `Stats`, а остальные поля позволяют определить источник, состояние, срок действия и связи с другими списками.

**Зачем нужен:** движку недостаточно знать «есть прибавка +7». Нужно знать, к какому эффекту она относится и какой список отсоединить, когда этот эффект перестал действовать. Отдельный список позволяет обрабатывать связанные значения как одну группу с общим контекстом.

**Что содержит:** внутри `Stats` находится заголовок [D2StatsArrayStrc](#d2statsarraystrc). Его элементы лежат отдельно по `Stats.pStat`. Поля `pPrevLink`, `pNextLink` и `pParent` содержат адреса других списков, а не копии их значений.

**Куда входит:** может быть присоединён к организации характеристик объекта. Кроме того, является базовой частью [D2StatListExStrc](#d2statlistexstrc), описанной следующим пунктом.

**Кто заполняет:** создание эффекта и подсистема списков. Это данные работы игры, а не строка настроек геймдизайнера.

| Поле | Тип | Что хранится | Где используется и зачем |
|---|---|---|---|
| `pMemPool` | `void*` | Контекст выделения памяти | Создание массива и освобождение списка используют нужный пул памяти |
| `pUnit` | [D2UnitStrc*](#d2unitstrc) | Объект, к которому присоединён список | Изменение или удаление списка определяет объект, для которого действует этот вклад |
| `dwOwnerType` | `uint32_t` | Тип объекта-источника списка | Поиск и фильтрация различают, например, предметный и другой источник |
| `dwOwnerId` | `uint32_t` | ID объекта-источника | Вместе с `dwOwnerType` определяет, от какого объекта происходит список. Это не величина бонуса |
| `dwFlags` | `uint32_t` | Флаги из `D2C_StatlistFlags` | Код выбирает цепочку присоединения, проверяет условия обработки и временные признаки |
| `dwStateNo` | `uint32_t` | ID связанного состояния | Поиск находит список определённого состояния, удаление может выключить соответствующее состояние |
| `dwExpireFrame` | `int32_t` | Временная граница или счётчик по правилам используемого пути | Обновление времени определяет, когда временный список должен перестать действовать |
| `dwSkillNo` | `uint32_t` | ID умения, связанного с эффектом | Сохраняет контекст происхождения эффекта умения. Не заменяет ID характеристики в записи |
| `dwSLvl` | `uint32_t` | Уровень связанного умения | Сохраняет уровень источника эффекта. Не означает, что все значения списка равны этому числу |
| `Stats` | [D2StatsArrayStrc](#d2statsarraystrc) | Вложенный контейнер собственных характеристик списка | Здесь получают значения этого списка, отдельно от итогов всех присоединённых источников |
| `pPrevLink` | [D2StatListStrc*](#d2statliststrc) | Адрес предыдущего списка в цепочке | Поиск перебирает списки в обратном направлении |
| `pNextLink` | [D2StatListStrc*](#d2statliststrc) | Адрес следующего списка в цепочке | При отсоединении исправляются ссылки соседей, чтобы цепочка осталась связной |
| `pParent` | [D2StatListStrc*](#d2statliststrc) | Адрес родительской организации списка | Отсоединение находит родителя и убирает список из его цепочки |
| `fpStatRemove` | `StatListRemoveCallback` | Адрес функции дополнительной обработки удаления | Когда предусмотрено эффектом, удаление вызывает код завершения эффекта |

Объявление в исходнике: [D2StatListStrc](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/include/D2StatList.h#L465).

#### 4.4.3. `D2StatListExStrc`

**Что это:** расширенная организация характеристик объекта. На неё указывает поле `pStatListEx` структуры [D2UnitStrc](#d2unitstrc).

**Зачем нужна:** объект может иметь собственные значения и несколько присоединённых источников. Нужны доступ к источникам и отдельное представление итоговых характеристик для расчётов.

**Что наследует:** все поля [D2StatListStrc](#d2statliststrc), включая `Stats`. В C++ это наследование, поэтому отдельного поля с именем «Базовая часть» в исходнике нет. Унаследованный `Stats` и собственный `FullStats` — два разных поля.

**Различие данных:** `Stats` хранит собственные записи базовой части списка. `FullStats` обслуживает итоговые значения с учётом применимых вкладов и правил характеристик. Присоединённые списки сохраняют возможность различить источники и убрать нужный вклад. Итог не следует считать безусловной суммой всех существующих списков, потому что учитываются флаги, условия и специальные операции.

**Кто заполняет:** подсистема характеристик при создании объекта, присоединении, изменении и отсоединении эффектов.

| Собственное поле расширения | Тип | Что хранится | Где используется и зачем |
|---|---|---|---|
| `pMyLastList` | [D2StatListStrc*](#d2statliststrc) | Последний элемент основной цепочки присоединённых списков | Отсюда поиск начинает обход по `pPrevLink`, чтобы найти нужный источник, флаг или состояние |
| `pMyStats` | [D2StatListStrc*](#d2statliststrc) | Последний элемент отдельной цепочки `STATLIST_SET` | Фильтрация направляет запрос в эту цепочку, когда нужен соответствующий признак |
| `pOwner` | [D2UnitStrc*](#d2unitstrc) | Адрес объекта-владельца расширенной структуры | Перерасчёт получает объект, характеристики которого обслуживает эта организация |
| `FullStats` | [D2StatsArrayStrc](#d2statsarraystrc) | Вложенный контейнер итоговых значений | Чтение итоговой характеристики использует подготовленный результат, а не настройки диапазона генерации |
| `ModStats` | [D2ModStatsArrayStrc](#d2modstatsarraystrc) | Вложенный контейнер отслеживаемых ключей | Последующая обработка перебирает ключи характеристик, для которых предусмотрен учёт изменений. В его элементах нет `nValue` |
| `StatFlags` | `uint32_t*` | Адрес битовых массивов состояний | Переключение состояния меняет соответствующий бит и отметку обновления |
| `pfOnValueChanged` | `StatListValueChangeFunc` | Адрес функции реакции на изменение значения | Изменение характеристики вызывает предусмотренную дополнительную игровую обработку |
| `pGame` | `D2GameStrc*` | Адрес игрового контекста | Передаёт контекст предусмотренным обработчикам изменения |

Объявление в исходнике: [D2StatListExStrc](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/include/D2StatList.h#L485).

#### 4.4.4. Пример различия источника и итога

Условный технический пример одной обычной складываемой характеристики. Он показывает смысл хранения, а не утверждает конкретную раскладку списков реального уникального предмета.

| Где находятся данные | Что хранится | Для чего сохраняется отдельно |
|---|---|---|
| `Stats` расширенного списка объекта | Собственное значение 10 | Получить собственную величину, не потеряв её после применения эффекта |
| `Stats` присоединённого списка эффекта | Прибавка 7 | Найти и отсоединить именно этот источник |
| `FullStats` расширенного списка объекта | Итог 17 для этого простого случая | Получить действующую величину при расчёте |

После удаления эффекта собственное значение остаётся 10. При предусмотренном перерасчёте итог больше не включает 7. Именно поэтому контейнер собственных значений, список источника и итоговые данные не являются одной и той же структурой.

Для любого из этих контейнеров [D2StatsArrayStrc](#d2statsarraystrc) решает только задачу хранения массива. Происхождение и действие эффекта описывает [D2StatListStrc](#d2statliststrc). Организацию источников и итогов объекта обеспечивает [D2StatListExStrc](#d2statlistexstrc).

### 4.5. `D2StatStrc` — содержимое одного элемента массива

Объявления:

- [D2SLayerStatIdStrc](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/include/D2StatList.h#L415).
- [D2StatStrc](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/include/D2StatList.h#L440).

Это одна запись размером 8 байт. В её начале непосредственно находятся `nLayer` и `nStat`, после них — `nValue`. Здесь нет указателя на отдельную «базовую запись».

| Поле | Тип | Что означает число | Зачем код его читает |
|---|---|---|---|
| `nLayer` | `uint16_t` | Выбирает вариант внутри одной характеристики. Для обычной силы равен 0. Для бонуса отдельного умения хранит ID умения | Поиск отличает, например, прибавку к умению №50 от прибавки к умению №51 при одном и том же `nStat`. Оба бонуса должны оставаться разными записями |
| `nStat` | `uint16_t` | Определяет вид характеристики: например, `STAT_STRENGTH` — сила, `STAT_ITEM_SINGLESKILL` — прибавка отдельного умения | Код выбирает смысл `nLayer` и `nValue`, находит правило характеристики и выполняет нужный расчёт |
| `nValue` | `int32_t` | Хранит величину выбранной характеристики. Для силы +7 при масштабе 1 это 7. Для бонуса умения +2 это 2 | Расчёт использует величину, а не настройки диапазона, из которого она была получена. Специальные характеристики могут упаковывать несколько чисел |

В C++ первые два поля объявлены в [D2SLayerStatIdStrc](#d2slayerstatidstrc), а [D2StatStrc](#d2statstrc) наследует их и добавляет `nValue`. Поэтому в полном объекте доступны все три поля, а не три разных объекта.

Подробные правила, смещения, поиск по двум полям и примеры применения: [D2StatStrc — описание полей](#d2statstrc).

### 4.6. `D2ItemStatCostTxt` — правила хранения, обработки и описания характеристики

**Что это:** одна запись общих правил для одного вида характеристики. Например, у силы есть своё описание правил, а у сопротивления огню — другое.

**Зачем нужна:** запись [D2StatStrc](#d2statstrc) сообщает «какая характеристика, какой параметр, какое число». Но она не хранит, сколько бит нужно для записи этого числа в файл, как учитывать внутренний масштаб и какой текст показать игроку. Эти правила находятся в [D2ItemStatCostTxt](#d2itemstatcosttxt).

**Кто задаёт:** автор игровых данных настраивает соответствующую строку [ItemStatCost.txt](https://d2r-tools.com/data/itemstatcost). Загрузчик преобразует данные в таблицу правил. Автор выбирает поддерживаемые движком операции и функции описания, а не записывает новый исполняемый алгоритм в текстовый файл.

**Где находится:** в общем массиве `pItemStatCostTxt`, отдельно от предметов. Для одной характеристики её правила общие, даже если у разных предметов различаются значения.

**Как связана с предметом:** поле `nStat` записи [D2StatStrc](#d2statstrc) служит индексом правил. Функция [ITEMS_GetItemStatCostTxtRecord](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/src/Items/Items.cpp#L7385) проверяет границы и возвращает адрес `pItemStatCostTxt[nStatId]`. Внутри `D2StatStrc` нет указателя на эту таблицу и нет копии всех её настроек.

#### 4.6.1. Какие задачи обслуживают поля

| Поле | Что задаёт автор | Кто читает и какое действие выполняет |
|---|---|---|
| `nValShift` | Число бит внутреннего сдвига | Назначение переводит логическое число во внутренний масштаб. Сохранение учитывает обратное преобразование |
| `nSaveBits` | Сколько бит отведено значению свойства предмета | Запись и чтение знают, сколько бит занять или прочитать, не используя одинаковые 32 бита для каждой характеристики |
| `dwSaveAdd` | Смещение при кодировании | Запись прибавляет его к значению, чтение вычитает. Это правило представления числа, не дополнительный бонус персонажа |
| `dwSaveParamBits` | Сколько бит отведено дополнительному параметру | Сохранение определяет длину параметра, например сведений об умении |
| `nEncode` | Предусмотренный вариант специальной кодировки | Обработка сложных свойств знает, как упаковать или извлечь несколько чисел |
| `nDescFunc` | Номер способа формирования текста | Подсказка выбирает формат описания этой характеристики |
| `wDescStrPos` | Положительный вариант локализованного текста | Подсказка получает слова для описания положительного значения |
| `wDescStrNeg` | Отрицательный вариант локализованного текста | Подсказка получает слова для описания отрицательного значения |
| `nDescPriority` | Приоритет строки | Подсказка определяет порядок вывода свойства |
| `nOp` | Номер поддерживаемой операции | Перерасчёт применяет предусмотренное правило зависимости характеристик. Для разных операций нужны их собственные параметры |

Точные типы и отдельное описание остальных рассматриваемых полей: [D2ItemStatCostTxt — поля](#d2itemstatcosttxt).

#### 4.6.2. Пример «сила +7»

| Данные | Что в них находится | Что в них не находится |
|---|---|---|
| Заданная запись [D2PropertyStrc](#d2propertystrc) | Например, получить силу от 5 до 10 | Ещё не выбранное значение конкретного предмета |
| Полученная запись [D2StatStrc](#d2statstrc) | `nStat = STAT_STRENGTH`, `nLayer = 0`, значение +7 в нужном масштабе | Правила длины записи и текстовые шаблоны |
| Общая запись [D2ItemStatCostTxt](#d2itemstatcosttxt) для силы | Как представить, обработать и описать значение силы | Ни диапазон 5–10 этого аффикса, ни выпавшее 7 этого предмета |

Когда нужно сохранить предмет, код берёт число из `D2StatStrc` и параметры кодирования из записи правил силы. Когда нужно показать свойство, обработка описания использует фактическое число и правила текста. У второго предмета может быть сила +9, но правила силы остаются теми же.

Таким образом, эта структура нужна для **общих правил одного вида характеристики**, а не для хранения ещё одного набора бонусов предмета.

Объявление в исходнике: [D2ItemStatCostTxt](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/include/DataTbls/ItemsTbls.h#L235).

Проверенные места использования:

- [ITEMMODS_AddPropertyToItemStatList](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/src/Items/ItemMods.cpp#L2877) — читает правило масштаба при назначении значения.
- [ITEMS_SerializeItem](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/src/Items/Items.cpp#L6389) — читает правила записи характеристик.
- [_enhanceAttributeDescription](https://github.com/dschu012/d2s/blob/0da1e024b406fd4c3fffa182faebc6ed539c1cd7/src/d2/attribute_enhancer.ts#L162) — пример формирования описаний по этим данным в стороннем инструменте, не исходник UI движка D2R.

## 5. `D2ItemsTxt` и `D2ItemTypesTxt`

### 5.1. `D2ItemsTxt`

**Происхождение:** D2MOO 1.10f. Соответствующие таблицы D2R:

- [Weapons.txt](https://d2r-tools.com/data/weapons).
- [Armor.txt](https://d2r-tools.com/data/armor).
- [Misc.txt](https://d2r-tools.com/data/misc).

Эти ссылки ведут к документации конкретных таблиц, не к выгрузке игровых файлов.

**Расположение:** элемент общего массива описаний. **Владелец настроек:** автор игровых данных. **Потребители:** создание, графика, инвентарь, экипировка и расчёты.

Каждое поле описано отдельно. Указаны рассматриваемые поля предметной системы, а не все технические поля большого объявления. Поля перечислений, служебных областей движка и других подсистем нельзя считать описанными по аналогии.

| Поле | Тип | Что хранит | Кто заполняет | Где читается и для чего |
|---|---|---|---|---|
| `dwCode` | `uint32_t` | Код вида как одно число | Загрузчик из столбца `code` | Поиск вида по коду, например при связи описания уникального предмета с обычным видом |
| `szCode` | `char[4]` | Те же байты кода как символы | Та же область объединения, что у `dwCode` | Символьное представление кода. Не отдельная копия и не отображаемое название |
| `szInvFile` | `char[32]` | Имя обычного ресурса инвентаря | Загрузчик из `invfile` | Графическая подсистема выбирает изображение обычного варианта |
| `szUniqueInvFile` | `char[32]` | Имя варианта ресурса для уникального предмета | Загрузчик из `uniqueinvfile` | Выбор специального изображения, если оно предусмотрено данными |
| `szSetInvFile` | `char[32]` | Имя варианта ресурса для предмета комплекта | Загрузчик из `setinvfile` | Выбор оформления комплекта, не проверка его числовых бонусов |
| `nInvWidth` | `uint8_t` | Ширина занимаемой области в клетках | Загрузчик из `invwidth` | `ITEMS_GetDimensions` возвращает ширину для размещения в сетке |
| `nInvHeight` | `uint8_t` | Высота занимаемой области в клетках | Загрузчик из `invheight` | `ITEMS_GetDimensions` возвращает высоту для размещения в сетке |
| `nMinDam` | `uint8_t` | Нижняя граница исходного одноручного урона | Загрузчик из `mindam` | Расчёт одноручного урона берёт её как исходное число до соответствующих модификаторов |

| `n2HandMinDam` | `uint8_t` | Нижняя граница исходного двуручного урона | Загрузчик из `2handmindam` | Используется для двуручного способа применения соответствующего оружия |
| `n2HandMaxDam` | `uint8_t` | Верхняя граница исходного двуручного урона | Загрузчик из `2handmaxdam` | Используется для верхней границы двуручного урона |
| `dwMinAc` | `int32_t` | Минимальная исходная защита вида брони | Загрузчик из `minac` | Получение индивидуальной исходной защиты при создании брони |
| `dwMaxAc` | `int32_t` | Максимальная исходная защита вида брони | Загрузчик из `maxac` | Ограничивает диапазон исходной защиты. Специальные случаи имеют отдельные формулы |
| `nDurability` | `uint8_t` | Прочность, заданная виду | Загрузчик из `durability` | Инициализация прочности предмета. Износ меняет индивидуальные характеристики, а не это поле |
| `wReqStr` | `uint16_t` | Исходное требование силы | Загрузчик из `reqstr` | Расчёт требования для использования, включая предусмотренные модификаторы требований |
| `wReqDex` | `uint16_t` | Исходное требование ловкости | Загрузчик из `reqdex` | Расчёт требования ловкости. Отдельно от требования силы |
| `wType` | `int16_t[2]` | Два индекса категорий | Загрузчик преобразует `type` и `type2` | Проверки категории и общих правил. Элементы одного массива, не вложенные [D2ItemTypesTxt](#d2itemtypestxt) |

Изображение, размер и исходные значения не требуется целиком копировать в каждый предмет. В D2MOO размеры извлекаются из общего описания через `dwClassId`.

### 6.1. `D2MagicAffixTxt`

**Назначение:** описание одной возможной магической добавки. **Входит:** в общую таблицу аффиксов. **Содержит:** непосредственно вложенный массив `D2PropertyStrc pProperties[3]`.

| `dwMaxLevel` | `uint32_t` | Верхнее уровневое ограничение | Автор через таблицу | Исключение аффикса за пределами допустимого диапазона, с учётом правил пустого ограничения |
| `dwGroup` | `uint32_t` | Номер группы аффикса | Автор через таблицу | Исключает запрещённое сочетание добавок одной группы при выборе нескольких аффиксов |
| `wIType` | `uint16_t[7]` | Разрешённые категории предметов | Загрузчик по кодам категорий | Отбор проверяет, подходит ли категория создаваемого предмета |

### 6.2. `D2PropertyStrc`

**Назначение:** одна запись заданного свойства. Она описывает входы для функции назначения, а не хранит готовый экземпляр предмета.

Layout D2MOO 1.10f, всего 16 байт:

| Смещение | Поле | Тип | Что хранит | Кто заполняет | Где читается и для чего |
|---|---|---|---|---|---|
| `+0` | `nProperty` | `int32_t` | Индекс записи правила свойства | Загрузчик по коду свойства автора | Выбор [D2PropertiesTxt](#d2propertiestxt), определяющей обработчики и характеристики результата |
| `+4` | `nLayer` | `int32_t` | Дополнительный вход обработчика | Автор через параметр свойства | Например, определяет нужное умение. Для `PropertyFunc01` простого бонуса этот вход не становится параметром результата, функция назначает слой 0 |
| `+8` | `nMin` | `int32_t` | Нижнюю границу простого диапазона | Автор через минимум свойства | `ITEMMODS_PropertyFunc01` использует её как начало диапазона. Для других функций смысл нужно читать в их алгоритме |
| `+12` | `nMax` | `int32_t` | Верхнюю границу простого диапазона | Автор через максимум свойства | Та же функция определяет число вариантов до этой границы включительно. Это не готовое выпавшее значение |

Физически такие записи находятся внутри массивов общих описаний. В D2MOO это, например, три записи у аффикса, двенадцать у уникального предмета и семь у рунного слова. Число записей описания не равно гарантированному числу строк подсказки.

В D2R аналогичные входы видны как `code/param/min/max` соответствующих блоков таблиц. Это соответствие назначения данных, не доказательство одинаковой упаковки памяти.

`nProperty` не является значением [D2C_ItemStats](#d2c-itemstats): первое выбирает правило создания, второе именует характеристику результата.

Объявление: [D2PropertyStrc](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/include/DataTbls/ItemsTbls.h#L8). Поле `pProperties` описания аффикса показано в [D2MagicAffixTxt](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/include/DataTbls/ItemsTbls.h#L545).

### 6.3. Что означает дополнительный параметр

| Заданное свойство | Чего недостаточно без параметра | Что уточняет параметр |
|---|---|---|
| Прибавка силы | Дополнительных сведений не нужно | Для простого случая не используется |
| Прибавка отдельного умения | Известно количество уровней, но не умение | Какому умению назначить бонус |
| Сложный эффект умения | Одного числа недостаточно | Нужные обработчику сведения об эффекте |

Название `Layer` не означает графический слой. Параметр задания и `nLayer` результирующей характеристики нельзя автоматически копировать один в другой: обработчик может его игнорировать или преобразовать.

Простой обработчик: [ITEMMODS_PropertyFunc01](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/src/Items/ItemMods.cpp#L2828). Назначение результата: [ITEMMODS_AddPropertyToItemStatList](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/src/Items/ItemMods.cpp#L2877).

### 6.4. `D2PropertiesTxt`

**Назначение:** связать свойство автора с функциями и характеристиками движка. **Входит:** в общую таблицу правил. **Используется:** при назначении свойства экземпляру.

Соответствующая таблица D2R: [Properties.txt](https://d2r-tools.com/data/properties).

| Поле | Тип | Что хранит | Кто заполняет | Где читается и для чего |
|---|---|---|---|---|
| `wProp` | `uint16_t` | Служебное поле записи | Механизм загрузки таблицы | Точный самостоятельный смысл не установлен в этом разборе. Нельзя использовать как доказанный ID характеристики или придумать для него игровое действие |
| `nFunc` | `uint8_t[7]` | Семь номеров обработчиков | Загрузчик из `func1`–`func7` | Назначение выбирает функцию из таблицы функций движка и передаёт ей входы свойства |
| `wStat` | `uint16_t[7]` | Семь ID целевых характеристик | Загрузчик из `stat1`–`stat7` | Для обработчиков, использующих явную характеристику, определяет ID записи результата. Некоторые специальные функции выбирают характеристику сами |
| `nSet` | `uint8_t[7]` | Параметр каждого шага назначения | Загрузчик из `set1`–`set7` | В обычном пути управляет установкой либо прибавлением. Точный смысл зависит от выбранной функции |
| `wVal` | `uint16_t[7]` | Дополнительный аргумент каждого шага | Загрузчик из `val1`–`val7` | Обработчики специальных свойств используют аргумент по своей формуле. Это не общий контейнер с выпавшими значениями |

Индекс `i` связывает поля: `nFunc[i]`, `wStat[i]`, `nSet[i]`, `wVal[i]` относятся к одному шагу назначения. Это семь параллельных блоков, а не семь результатов случайной генерации.

Строка таблицы не содержит исполняемый код. Номер функции выбирает обработчик, уже реализованный в движке. Добавление совершенно нового поведения может требовать кода, а не только новой строки.

Объявление: [D2PropertiesTxt](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/include/DataTbls/ItemsTbls.h#L437). Пример обработчика: [ITEMMODS_PropertyFunc01](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/src/Items/ItemMods.cpp#L2828).

## 7. `D2C_ItemStats` и `D2ItemStatCostTxt`

### 7.1. `D2C_ItemStats`

Это перечисление числовых ID в исходнике D2MOO, не структура предмета и не массив значений. Пример имени — `STAT_STRENGTH`.

ID сообщает, что означает число: сила, сопротивление, урон, прочность или другое. Он не задаёт сам по себе случайный диапазон и не содержит результата конкретного предмета.

### 8.3. `D2StatStrc` — одна числовая характеристика

**Назначение:** хранить одно фактическое значение характеристики в массиве. Эта запись не содержит имя предмета, его графику или настройки случайного диапазона.

#### 8.3.1. Где физически находятся поля

Layout D2MOO 1.10f, всего 8 байт:

| Байты от начала записи | Поле | Тип | Размер |
|---|---|---|---|
| `+0` и `+1` | `nLayer` | `uint16_t` | 2 байта |
| `+2` и `+3` | `nStat` | `uint16_t` | 2 байта |
| `+4`–`+7` | `nValue` | `int32_t` | 4 байта |

В исходнике [D2SLayerStatIdStrc](#d2slayerstatidstrc) объявляет первые 4 байта, а [D2StatStrc](#d2statstrc) наследует эту структуру и добавляет ещё 4 байта значения. Это означает физическое присутствие унаследованных полей в начале записи. Отдельного адреса базовой структуры или операции «получить поле откуда-то» здесь нет.

`nPackedValue` — альтернативное 32-битное представление тех же первых четырёх байтов через `union`. Оно не занимает ещё четыре байта и не содержит `nValue`.

#### 8.3.2. Поле `nStat`

| Параметр поля | Описание |
|---|---|
| Что хранит | Числовой ID вида характеристики из перечисления [D2C_ItemStats](#d2c-itemstats) |
| Пример | `STAT_STRENGTH` означает силу. `STAT_ITEM_SINGLESKILL` означает прибавку к одному определённому умению |
| Кто записывает | Обработчик свойства выбирает целевую характеристику. При загрузке её ID восстанавливается из записи сохранения |
| Кто читает | Поиск характеристики, расчёт величины, кодирование сохранения и построение текста |
| Зачем нужен | Одно и то же число 7 может означать силу, сопротивление или другое действие. ID выбирает смысл числа и соответствующее правило [D2ItemStatCostTxt](#d2itemstatcosttxt) |
| Чего не означает | Это не ID предмета, не ID аффикса и не `D2PropertyStrc.nProperty` |

#### 8.3.3. Поле `nLayer`

| Параметр поля | Описание |
|---|---|
| Что хранит | Вторую числовую часть адреса характеристики. Её смысл определяется конкретным `nStat` и обработчиком |
| Когда равно 0 | Например, обычная прибавка силы не требует выбора умения или другого варианта. Простой обработчик назначает такую запись со слоем 0 |
| Когда хранит ID | Для прибавки отдельного умения хранит ID именно этого умения. Две записи с одним `STAT_ITEM_SINGLESKILL`, но разными ID умений, обозначают разные бонусы |
| Когда хранит упакованные числа | Для рассматриваемого событийного обработчика умения хранит одновременно ID и уровень умения по формуле ниже |
| Кто записывает | Функция назначения свойства формирует параметр. Загрузчик восстанавливает его по правилам кодирования характеристики |
| Кто читает | Поиск передаёт вместе `nStat` и `nLayer`, чтобы получить нужную запись. Обработчик специального эффекта извлекает сведения о выбранном умении |
| Зачем нужен | Без него можно было бы хранить только одно значение общего вида «прибавка умения», не различая, какому умению оно принадлежит |
| Чего не означает | Не слой изображения, не порядковый номер строки подсказки и не универсальный ID предмета |

**Пример отдельного умения:** [ITEMMODS_PropertyFunc22](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/src/Items/ItemMods.cpp#L4145) передаёт параметр `D2PropertyStrc.nLayer` в назначаемую характеристику, приведя его к `uint16_t`. При свойстве бонуса отдельного умения это позволяет сохранить выбранный ID умения.

**Пример составного параметра:** [ITEMMODS_PropertyFunc11](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/src/Items/ItemMods.cpp#L3635) формирует параметр так:

```text
nLayer = (SkillID << 6) + (SkillLevel & 63)

SkillID    = nLayer >> 6
SkillLevel = nLayer & 63
```

Младшие 6 бит хранят уровень, остальные — ID умения. Это правило конкретного обработчика. Применять такую распаковку к обычной силе или любому другому `nLayer` нельзя.

Числовой пример: при условном ID умения 50 и уровне 3 параметр равен `50 * 64 + 3 = 3203`. Это одно поле `uint16_t`, внутри которого размещены два числа.

#### 8.3.4. Поле `nValue`

| Параметр поля | Описание |
|---|---|
| Что хранит | Фактическое значение выбранной характеристики, а для некоторых характеристик — несколько упакованных значений |
| Простой пример | Для прибавки силы +7 при `nValShift = 0` хранит 7. Диапазон генерации 5–10 в это поле не записывается |
| Пример умения | Для прибавки +2 к умению хранит величину 2, а ID умения расположен в `nLayer` |
| Кто записывает | Генерация свойства, последующее изменение характеристики либо восстановление из сохранения |
| Кто читает | Расчёты действия эффекта. Формирование текста и сериализация используют нужные правила преобразования |
| Почему недостаточно вывести число напрямую | У характеристики может быть внутренний масштаб `nValShift` либо специальная упаковка нескольких величин |

Для обычного масштабируемого назначения в [ITEMMODS_AddPropertyToItemStatList](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/src/Items/ItemMods.cpp#L2877):

```text
Внутреннее значение = Логическое значение << nValShift
```

Например, при заданном правиле `nValShift = 8` логическое число 7 представляется как 1792. Это условный пример масштаба, а не утверждение, что сила хранится с таким сдвигом.

Для характеристики `STAT_ITEM_CHARGED_SKILL` код [ITEMMODS_PropertyFunc19](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/src/Items/ItemMods.cpp#L3787) записывает количество зарядов в одном значении:

```text
nValue = (MaximumCharges << 8) + CurrentCharges

CurrentCharges = nValue & 255
MaximumCharges = nValue >> 8
```

Например, 12 текущих зарядов из 20 дают `20 * 256 + 12 = 5132`. Число 5132 не является показанным игроку количеством зарядов. Код [ITEMMODS_GetItemCharges](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/src/Items/ItemMods.cpp#L539) получает текущие заряды из младшего байта. Код [ITEMMODS_UpdateItemWithSkillCharges](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/src/Items/ItemMods.cpp#L605) изменяет текущую часть, сохраняя максимальную.

У зарядов `nLayer` отдельно идентифицирует умение и его уровень. Его формула использует параметры кодировки из таблиц, поэтому нельзя переносить на него любое правило без проверки. Наличие одного поля `nValue` не означает, что для всех характеристик действует одна интерпретация числа.

#### 8.3.5. Зачем поиск использует два поля

Условные ID умений 50 и 51 в следующей таблице не обозначают выбранные реальные названия умений игры. Пример показывает различие ключей.

| Запись | `nStat` | `nLayer` | `nValue` | Смысл |
|---|---|---|---|---|
| А | `STAT_STRENGTH` | 0 | 7 | Сила +7 при масштабе 1 |
| Б | `STAT_ITEM_SINGLESKILL` | 50 | 2 | Прибавка +2 к умению с ID 50 |
| В | `STAT_ITEM_SINGLESKILL` | 51 | 1 | Прибавка +1 к другому умению с ID 51 |

Запрос силы использует пару `(STAT_STRENGTH, 0)` и получает 7. Запрос бонуса умения 50 использует `(STAT_ITEM_SINGLESKILL, 50)` и получает 2. Запись В не подходит второму запросу и не превращает его результат в 3.

В D2MOO первые два поля доступны для сравнения как `nPackedValue`. Логическое представление ключа на рассматриваемой платформе:

```text
Key = (nStat << 16) | nLayer
```

Упорядоченный поиск работает с этим ключом. `nValue` не входит в ключ, поэтому изменение величины не означает смену характеристики или умения.

[D2StatStrc](#d2statstrc) не является всем предметом и не содержит [D2PropertyStrc](#d2propertystrc). Входные настройки генерации и полученное значение — разные записи.

Объявления:

- [D2SLayerStatIdStrc](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/include/D2StatList.h#L415).
- [D2StatStrc](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/include/D2StatList.h#L440).

## 9. Контракт создания и назначения

Ниже последовательность рассматриваемого участка генерации. Полный алгоритм выпадения, редкости и выбора всех аффиксов сюда не входит.

| Шаг | Читается | Записывается |
|---|---|---|
| 1. Выбран вид | Общее описание вида | Идентификатор вида экземпляра |
| 2. Создан объект | Настройки создания | Индивидуальные сведения и состояние |
| 3. Выбран аффикс | Условия и веса | ID выбранного аффикса |
| 4. Обработана запись свойства | `nProperty`, параметр, границы | Пока только промежуточный результат |
| 5. Выполнено правило | Функция и целевая характеристика | Значение в нужном списке |

Для простого равномерного выбора при `min <= max`:

```text
N = max - min + 1
R = случайное целое от 0 до N - 1
V = min + R
```

Если `min = max`, значение фиксировано. Эти формулы относятся к простому обработчику диапазона и не описывают все специальные свойства.

При назначении может применяться внутренний масштаб:

```text
Vinternal = V << ValShift
```

Обработчик либо устанавливает значение, либо добавляет его к существующему, если выбран соответствующий режим. Нельзя задавать универсальное правило «все свойства всегда только складываются».

При повторном открытии инвентаря, переносе или выводе подсказки уже полученное значение не должно заново выбираться из диапазона.

Исходные функции:

- [ITEMMODS_PropertyFunc01](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/src/Items/ItemMods.cpp#L2828).
- [ITEMMODS_AddPropertyToItemStatList](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/src/Items/ItemMods.cpp#L2877).

Операции со списками: [D2StatList.cpp](https://raw.githubusercontent.com/ThePhrozenKeep/D2MOO/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/src/D2StatList.cpp). Последнее требование описывает сохранение идентичности экземпляра, а не утверждает, что оригинальный движок нигде не выполняет внутреннюю повторную распаковку или перерасчёт.

## 10. Расчёт и текстовое описание

### 10.1. Три разных результата

| Представление | Содержимое |
|---|---|
| Полученные свойства экземпляра | Сила +7, сопротивление огню +13 |
| Рассчитанные параметры предмета/героя | Урон, защита, итоговая сила |
| Строки подсказки | Человекочитаемое описание, иногда с объединением записей |

Одна строка не обязана соответствовать одной записи и одному аффиксу. Например, несколько сопротивлений могут получить общее описание. Два эффекта с разными адресатами, такими как разные умения, нельзя безусловно слить в одну строку.

Свойство силы предмета отображает его бонус, а не полную силу героя. Итоговое значение героя учитывает действующие источники.

В инструменте `d2s` явно разделены исходные, объединённые и отображаемые наборы. Это свидетельство представления инструмента, не буквальное объявление внутренних списков UI D2R.

Исходные функции инструмента:

- [_groupAttributes](https://github.com/dschu012/d2s/blob/0da1e024b406fd4c3fffa182faebc6ed539c1cd7/src/d2/attribute_enhancer.ts#L529).
- [_enhanceAttributeDescription](https://github.com/dschu012/d2s/blob/0da1e024b406fd4c3fffa182faebc6ed539c1cd7/src/d2/attribute_enhancer.ts#L162).

### 10.2. Урон и защита

Исходное описание остаётся общим, но рассчитанный параметр экземпляра может учитывать бонусы. Подсказка способна показывать итоговый урон/защиту и одновременно отдельные строки свойств.

Простой пример порядка операций, без дополнительных условий боя:

```text
Исходный максимум урона = 80
Увеличение урона оружия = 200%
Плоская прибавка к максимуму = 20

Итоговый максимум = 80 * (100 + 200) / 100 + 20 = 260
```

Это не полная формула физического урона персонажа. Она иллюстрирует опубликованный Blizzard порядок для такого сочетания свойств оружия. Ауры, характеристики героя, тип оружия, специальные эффекты и округления требуют собственных правил.

Официальная справка Blizzard: [Basic Item Information](https://classic.battle.net/diablo2exp/items/basics.shtml).

### Защита, проверка попадания и процентное усиление урона

Это описание механики Diablo II, используемой как источник для изучения D2R. Оно не устанавливает формулы боя для HoMM.

#### Проверка попадания

Для атаки, которая проверяет рейтинг атаки против защиты цели:

```text
Шанс попадания (%) =
    100 × AR / (AR + Defense)
        × 2 × уровень атакующего / (уровень атакующего + уровень цели)

AR — рейтинг атаки атакующего.
Defense — показатель защиты цели.
Обычный результат проверки ограничивается диапазоном 5–95%.
```

При одинаковых уровнях множитель уровней равен 1:

| AR | Defense | Шанс попадания |
|---:|---:|---:|
| 1000 | 500 | ≈ 66,7% |
| 1000 | 1000 | 50% |
| 1000 | 3000 | 25% |

Defense уменьшает вероятность попадания. Само это число не уменьшает урон уже попавшей атаки. Формула и назначение величин приведены в [официальном руководстве Blizzard, Character Information](https://classic.battle.net/diablo2exp/basics/characters.shtml).

Применимость проверки определяется способом атаки, а не типом урона. Заклинания обычно не проверяют AR против Defense. Это не означает гарантированное попадание любого снаряда: он может не пересечь цель. Если обычный удар с проверкой попадания несёт дополнительный урон огнём или холодом, промах такого удара не превращается в попадание его стихийной добавки. Процент попадания и сопротивление получаемому урону — разные проверки.

#### Enhanced Defense и уменьшение урона

| Название | Характеристика Diablo II | Назначение |
|---|---|---|
| Enhanced Defense | `item_armor_percent`, ID 16 | Процентное повышение показателя защиты предмета. В проектном списке соответствует `ITEM_PROPERTY_ARMOR_PERCENT` |
| Физическое сопротивление | `damageresist`, ID 36 | Процентное изменение получаемого физического урона. В проектном списке соответствует `ITEM_PROPERTY_DAMAGERESIST` |

Увеличение показателя защиты на 50% не равно снижению входящего урона на 50%. Для обычной брони, созданной с Enhanced Defense, Blizzard описывает расчёт `floor((maxac + 1) × (100 + ED) / 100)`, где `maxac` — верхняя граница базовой защиты, `ED` — процент Enhanced Defense. Поэтому простое умножение уже показанного числа защиты не описывает все случаи создания брони. См. [официальное описание Superior Armor и Enhanced Defense](https://classic.battle.net/diablo2exp/items/basics.shtml).

#### Enhanced Damage и максимальный урон

| Запись | Назначение |
|---|---|
| `item_maxdamage_percent`, ID 17 | Процент усиления максимального урона |
| `item_mindamage_percent`, ID 18 | Процент усиления минимального урона |
| Свойство `dmg%` | Обычное Enhanced Damage. Вызывает обработчик 7, обычно записывающий одинаковый процент в обе характеристики |

Для условного оружия с уроном 10–20, без других бонусов:

- Только +50% максимального урона даёт 10–30.
- Обычное +50% Enhanced Damage на оружии даёт 15–30.

В проектном списке `ITEM_PROPERTY_DAMAGE_PERCENT` обозначает общее усиление обеих границ, `ITEM_PROPERTY_MAXDAMAGE_PERCENT` — только верхней. Это проектные идентификаторы, их автоматически назначаемые числа не являются ID Diablo II.

Источники, каждый по своему назначению:

- [Данные характеристик D2R, itemstatcost.json](https://raw.githubusercontent.com/blizzhackers/d2data/master/json/itemstatcost.json) — искать `item_armor_percent`, `damageresist`, `item_maxdamage_percent`, `item_mindamage_percent`.
- [Данные свойств D2R, properties.json](https://raw.githubusercontent.com/blizzhackers/d2data/master/json/properties.json) — искать `"dmg%"`, поле `func1` содержит 7.
- [Реконструкция кода Diablo II, ItemMods.cpp](https://github.com/ThePhrozenKeep/D2MOO/blob/e2f21ad4ccb9d823fe8d55aa3f6a16732d61af19/source/D2Common/src/Items/ItemMods.cpp) — искать `ITEMMODS_PropertyFunc07` и назначения `STAT_ITEM_MINDAMAGE_PERCENT`, `STAT_ITEM_MAXDAMAGE_PERCENT`. Это код D2MOO, не опубликованный исходник D2R.

## 11. Сквозные примеры

Все записи этого раздела условные. Слова в скобках обозначают выбранное описание, а не реальные номера строк игровых файлов.

### 11.1. Обычный меч

```text
Общая запись вида
    Вид: короткий меч
    Графика и размер: заданы общим описанием
    Исходный урон: 3-7

D2UnitStrc, предмет А
    Вид → короткий меч
    Качество: обычное
    Положение: инвентарь, клетка 2,1
    Дополнительных магических бонусов в примере нет
```

Отсутствие магических бонусов не означает отсутствия вообще любых внутренних характеристик, например прочности.

### 11.2. Два меча с одной добавкой

```text
Общая запись аффикса
    pProperties[0]
        свойство → прибавка силы
        минимум = 5
        максимум = 10

D2UnitStrc, предмет А
    Вид → короткий меч
    Выбранная добавка → указанное описание аффикса
    Характеристика: сила +7

D2UnitStrc, предмет Б
    Вид → короткий меч
    Выбранная добавка → то же описание аффикса
    Характеристика: сила +10
```

Различаются фактические значения и идентичность объектов. Общие описания вида и аффикса не дублируются целиком.

### 11.3. Кольцо с двумя эффектами

```text
Задано автором
    Свойство 1: сила 5-10
    Свойство 2: сопротивление огню 10-20

Получено экземпляром
    Сила +7
    Сопротивление огню +13

Подсказка кольца
    +7 к силе
    Сопротивление огню +13%
```

Это две разные характеристики. Их не складывают друг с другом. Если собственная сила героя 30 и единственный действующий бонус силы равен 7, итог равен 37, но кольцо продолжает описываться как «+7».

### 11.4. Фиксированное свойство

```text
Задано: сила, min = 4, max = 4
Получено: сила +4
```

Тот же простой диапазон допускает фиксированный результат. Слово «свойство» не означает обязательную случайность.

### 11.5. Одно свойство и несколько характеристик

```text
Задано: все сопротивления 5-10
Выбрано: 7

Логический результат
    Сопротивление огню +7
    Сопротивление холоду +7
    Сопротивление молнии +7
    Сопротивление яду +7

Возможное объединённое описание
    Все сопротивления +7
```

Повторное использование выбранного значения определяется конкретными функциями свойства. Нельзя независимо бросать четыре числа только из-за наличия четырёх результирующих характеристик.

### 11.6. Два разных умения

```text
Характеристика: бонус отдельного умения
    Параметр: умение А
    Значение: +2

Характеристика: бонус отдельного умения
    Параметр: умение Б
    Значение: +1
```

Это разные ключи. Результат не равен «любое умение +3». Здесь видна необходимость дополнительного параметра.

### 11.7. Два источника одной прибавки

Условный пример обычных аддитивных бонусов в одном применимом контексте:

```text
Источник А: сила +7
Источник Б: сила +3
Итоговый бонус: сила +10
```

При группировке обычных одинаковых бонусов описание может показывать сумму. Отдельные условные списки, эффекты с разным параметром и специальные обработчики требуют собственных правил. Из этого примера не следует универсальная операция над всеми свойствами игры.

## 12. Сохранение предмета

Физическая структура памяти и запись в файле — разные представления. Файл не обязан содержать копию [D2UnitStrc](#d2unitstrc) со всеми указателями.

Для рассматриваемых форматов сохранения инструмент читает ID характеристики шириной 9 бит, затем предусмотренные её описанием параметры и значения. Маркер `511` завершает список. Связанные характеристики и сложные эффекты имеют специальные правила.

В простом случае кодирование значения имеет вид:

```text
Vencoded = Vlogical + SaveAdd
Vlogical = Vencoded - SaveAdd
```

Внутренний масштаб и специальные кодировки учитываются отдельно. Число бит определяет описание характеристики и версия формата, а не общий размер `int32_t` в памяти.

В сериализации также отдельно обрабатываются качество, размещение, прочность, количество, сокеты и дополнительные списки. Нельзя заключать, что весь предмет — только один список свойств.

| Поле | Тип | Что хранит | Кто заполняет | Для чего используется |
|---|---|---|---|---|

## 13. Проверяемые условия понимания системы

Эти условия служат примерами для проверки будущего разбора или адаптации. Они не являются отчётом о запуске игры или тестов HoMM.

| Ситуация | Ожидаемое различие |
|---|---|
| Созданы два одинаковых вида | Общее описание одно, экземпляры разные |
| Один аффикс дал 7 и 10 | ID аффикса может совпадать, значения экземпляров различаются |
| Предмет перемещён | Полученные свойства сохраняются |
| Подсказка открыта повторно | Значение не выбирается заново |
| Прочность уменьшилась | Меняется экземпляр, общий вид остаётся прежним |
| Два бонуса разных умений | Параметр сохраняет различие |
| Четыре сопротивления объединены текстом | Числовые данные не обязаны становиться одной характеристикой |
| Сохранение прочитано | Логические значения восстанавливаются с учётом формата |
| Автор добавил новую строку свойства | Используется существующий обработчик, новое поведение не возникает само |
